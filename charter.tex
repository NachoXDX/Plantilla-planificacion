\section{1. Descripción técnica-conceptual del proyecto a realizar}
\label{sec:descripcion}

Un robot puede definirse de forma muy simplista como una máquina compuesta por actuadores y sensores, mediante los que puede interactuar con el mundo. Esta forma reduccionista permite ver uno de los desafíos que la robótica enfrenta, que es la de responder a la pregunta ¿Cómo debo configurar mis actuadores para lograr la posición deseada? La respuesta a esta pregunta es la cinemática inversa (IK).

Encontrar dicha respuesta puede resultar muy complejo cuando consideramos robots de muchos grados de libertad, aún más si extendemos la discusión a robots flexibles, que teóricamente cuentan con infinitos de ellos. Esto último motiva la idea de encontrar métodos que permitan simplificar esta tarea, lo que directamente incurre en la disminución de tiempos de desarrollo. En la figura \ref{fig:morfologia} se observa el tipo de robot sobre el que se realizará el proyecto, este se compone de 4 tendones y 1 núcleo de nitinol que puede ser introducido o retraído para variar la rigidez de su cuerpo.

\begin{figure}[htpb]
\centering 
\includegraphics[width=.40\textwidth]{./Figuras/morfologia.png}
\caption{Robot Flexible}
\label{fig:morfologia}
\end{figure}


Con el fin de abordar esta problemática se propone evaluar la aplicación de \textit{Machine Learning} (ML) para obtener un modelo de IK que produzca resultados aceptables en términos de precisión y tiempos de cómputo. En la figura \ref{fig:diag_bloques} se observa el sistema propuesto, este aprenderá de un conjunto de datos que incluye tanto posiciones como estado de actuadores y luego deberá ser capaz de brindar la configuración necesaria para lograr una posición deseada.


\begin{figure}[htpb]
\centering 
\includegraphics[width=0.6\textwidth]{./Figuras/diag_bloques.png}
\caption{Diagrama en bloques}
\label{fig:diag_bloques}
\end{figure}


Abordar esta problemática utilizando ML es algo que se ha explorado previamente en otros trabajos. Los resultados obtenidos han sido satisfactorios pero no se han encontrado aplicaciones en el tipo de morfología propuesta. Esto último brinda una oportunidad para hacer un aporte e innovar en el ámbito de la robótica.

\section{3. Propósito del proyecto}
\label{sec:proposito}

Diseñar e implementar un modelo de ML capaz de predecir la configuración de actuadores necesaria para lograr una posición objetivo, haciendo uso de un conjunto de datos que recopile estados del robot, sin dejar de lado la complejidad computacional a los fines de que sea viable para operaciones en tiempo real.

a) Identificación de los riesgos y estimación de sus consecuencias:
 
Riesgo 1. Implementación errónea del modelo de cinemática directa. 
\begin{itemize}

	\item Ocurrencia (O): 5.
	
	La falta de experiencia a la hora de hacer este tipo de actividad supone una probabilidad de ocurrencia media.
\end{itemize}

\begin{itemize}
	\item Severidad (S): 6.
	
	Si el modelo resulta ser muy demandante en recursos para ser entrenado, se prolongará el tiempo que inicialmente fue estipulado.
	\item Ocurrencia (O): 3.
	
	Es difícil estimar su probabilidad de ocurrencia al desconocer el tipo de modelo que será utilizado. De todos modos, considerando el volumen de datos que se pretende usar, esto quizá no sea muy probable.
\end{itemize}

\begin{itemize}
	\item Severidad (S): 7.

\section{14. Gestión de la calidad}
\label{sec:calidad}

En esta sección se presentan los requisitos más relevantes junto a sus acciones de verificación y validación.

\begin{itemize} 

\item Req 1.1. El sistema deberá recibir una coordenada en el espacio (X,Y,Z).
\begin{itemize}
	\item Verificación: se incluirán pruebas unitarias que verifiquen que el sistema solo es capaz de recibir datos de la forma deseada y que responda de forma controlada cuando no.
	\item Validación: se realizarán pruebas de usuario donde un operador introducirá coordenadas a través de la interfaz para confirmar que el sistema acepta la orden.
\end{itemize}

\item Req 1.2. El sistema deberá devolver una configuración de actuadores (m1, m2, m3, m4, m5).
\begin{itemize}
	\item Verificación: se incluirán pruebas unitarias que verifiquen que el sistema produce datos de la forma deseada, tanto en casos de posiciones válidas como inválidas.
	\item Validación: se realizarán pruebas de usuario en que un operador introducirá coordenadas a través de la interfaz para confirmar que se produce la salida esperada.
\end{itemize}

\item Req 1.4. El sistema deberá indicar la certidumbre de la predicción.
\begin{itemize}
	\item Verificación: se implementarán pruebas unitarias para verificar que el algoritmo nunca arroja valores de certidumbre fuera del rango entre 0 y 1.
	\item Validación: se realizarán pruebas de usuario en que un operador introducirá coordenadas a través de la interfaz para confirmar que se recibe la certidumbre de la salida obtenida.
\end{itemize}

\item Req 1.5. El sistema deberá poder ser re entrenado fácilmente.
\begin{itemize}
	\item Verificación: se definirá claramente el \textit{pipeline} de entrenamiento y se automatizará mediante \textit{scripts} para verificar que el modelo responde sin errores al recibir nuevos conjuntos de datos.
	\item Validación: se solicitará que un colega entrene el modelo con un conjunto de datos propio para luego evaluar su experiencia en el proceso.
\end{itemize}

\item Req 1.6. El sistema deberá tener una exactitud de al menos 3 mm.
\begin{itemize}
	\item Verificación: se verificarán las predicciones con un conjunto de datos no observados por el modelo, utilizando como métrica al error medio cuadrático.
	\item Validación: se contrastarán salidas producidas por el sistema con el modelo de cinemática directa para evaluar su grado de exactitud.
\end{itemize}

\item Req 3.1. Se deberá corroborar la integridad de los datos de entrenamiento.
\begin{itemize}
	\item Verificación: se realizará un análisis exploratorio de datos para identificar posibles errores.
	\item Validación: se presentará un tablero con gráficos que permitan detectar errores de manera visual.
\end{itemize}

\item Req 4.1. La interfaz deberá mostrar el estado del robot.
\begin{itemize}
	\item Verificación: se medirá la latencia desde que se emite un cambio de estado en el robot hasta que este se muestra en la interfaz, verificando que este se mantenga por debajo de los 300 ms.
	\item Validación: se solicitará a un usuario que interactué con la interfaz y evalúe si esta representa al robot de manera satisfactoria.
\end{itemize}

\item Req 5.1. El sistema deberá tener una API web.
